# 比較計画・合否条件

## 検証する仮説

原文付きの対照事例を保持するBは、同じ資料を抽象文へ圧縮するCより、正式ルールの適用を安定させるか。どちらもAより改善するか。

Bが勝っても「圧縮が原因」と証明したとは言わない。情報量・文長・例示の具体性も異なる。トークン数を記録し、必要なら後日の独立実験で分離する。今回は同時に調整しない。

## 固定するもの

会社の現行コード、正式ルールと候補カタログ、各STEPのテンプレートと出力schema、入力原文、モデル/デプロイ/推論量/サンプリング設定、既存の段階分岐と再試行規則。キャッシュは文書取得・プロンプトのキャッシュと、モデル応答の再利用を区別する。独立反復でモデル応答を使い回さない。対応しないseed/temperatureは新たに設定しない。

Aは参照ゼロで、現行の呼出しに追加の共通指示を付けない。B/Cの参照ヘッダーは同じ。B/Cで先に候補を増減したり、正式ルール・対象特許の順番を変えたりしない。

## 事前登録

結果を読む前に以下をロックする。`tools/boundary_eval.py prepare` はその一部をJSONとSHA-256で固定する。

- 正解の出所と採用版、17件のID、同一特許・ファミリー・派生例を束ねたfamily_id。
- pilotと本試験の対象、除外理由、参照ID・順序、Cの生成入力と文章。正解に応じた参照選択はしない。
- 反復回数、A/B/Cの順序seed、追加順序テストと対照テストの範囲。
- 実時間・最大パイプライン数・既存LLM呼出し予算。価格が不明なら金額を作らず時間とtokensを報告する。
- 下記の採否条件。変更する必要がある場合は結果を見る前に理由と版を残す。

17件に同じ分類の例が1件しかないときは、除外後に何を学習例として残せるか確認する。対象由来の一般論を残して「leave-one-out」と言わない。参照不足は性能不足と混同しない。

## 3種類の評価を混ぜない

1. `seen_smoke`：対象の正解例を含めて動作を調べる。接続診断のみ。転移の成績には使わない。
2. `reference_excluded_known17`：対象のfamilyと派生資料をB/Cから除く。ただし既存Aは17件で調整済みなので、完全な未見テストではない。
3. `sealed_new_cases`：事例作成・一般化作成・調整に未使用の実特許。結果は確定版で一回の評価キャンペーンとして取得し、その場の修正へ戻さない。

例示として別案件の正解を使うことは学習であり禁止しない。今回の評価対象の答えを渡すことと区別する。正式ルール内の一般的な記載は除外対象ではないが、対象の正解を知って作った追加説明は派生資料として除く。

## 実施順序と停止

pilotは原則3系統＋逆側を含む最大6件・1反復。A/B/Cを同じ対象で実行する。Bが一件も改善せず、対照も区別できなければ見込みなしとして止める。1反復なので能力の最終結論とはしない。実装の不具合なら直して新run_idで再計測し、分類ロジックやカードの変更と混同しない。

本試験は予算が許せば17件×A/B/C×3反復。各試行は新しい会話・新しい段階状態から開始する。元のSTEP1から全部動かし、BのSTEP2出力をCへ使い回さない。A/B/Cの順は事前seedで均衡を意識して入れ替え、時間帯差を一方へ偏らせない。

完了しない試行を落とさない。APIエラー、schema失敗、タイムアウトはerror。本文確認未解決などの正常な保留はabstain。どちらも正解には数えない。予算で未実行ならinconclusive。

## 事前の採否基準

自動集計の候補条件：
- 予定されたA/B/Cと反復を完了している。
- Bの正答回数がAより増える案件が少なくとも1件ある。
- Bの正答回数がAより減る案件がゼロ。1件を直して他を壊すのを成功にしない。
- Aで出力が一定の案件について、Bで新しい揺れが生じていない。

満たしても即採用しない。追加の意味監査：
- 最終ラベルだけでなく、質問・取得事実・条件成立・工程対応・担当比較が原文と正式ルールに沿う。根拠の後付けを見逃さない。
- 3系統と逆側の正解を区別できる。対照が不足なら合格欄を空欄にして不足を報告する。
- 意味を保つ言い換え/段落の配置/無関係な効果追加では分類を保つ。分類を分ける事実を変えた対照では必要な判断が変わる。
- 最後に参照カードの順番変更でも大きな退行がないか、固定範囲で確認する。主実験の失敗を順序選びで救済しない。
- レビューは可能ならarm名・元正解の説明を隠して原文との対応を照合する。LLM単独採点を人手確定と扱わない。

Bの勝ちが「誤答→保留」だけなら分類改善とは言わない。保留削減と正答増加は別指標。Cについても同じ表を作る。Cが良くBが悪ければそのまま報告し、Bへ誘導しない。

`candidate_requires_semantic_and_transfer_review` は上記自動条件を満たした仮候補であり、17件の全問正解・顧客合格・本番採用を意味しない。既知17件しかない場合、未見性能は未検証とする。

## 失敗の記録単位

各案件で最初にずれた段階を記録する。STEP1の質問対象/条件、STEP2_PLANでの条件変質、STEP2_REVIEWの事実不足、同じ事実への意味判断、工程と実接続の混同、最終段の効果/手段/対象混同、前段の誤除外を区別する。語句の揺れだけと判断内容の揺れを分ける。

必要なら正しい中間事実を差し込む診断を別キャンペーンで行う。結果ラベルは入れない。本番フローの統合や前段無視ではない。

Bにも効果がなければ「対照事例の参照をこの条件では支持できなかった」で止める。永久に不可能とも、次の指示で必ず直るとも結論しない。
