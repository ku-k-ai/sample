# sample

特許分類の一次スクリーニング用プロンプトを生成する際、以下の設計原則を厳守すること。

1. 役割分離: これは一次スクリーニングであり最終分類ではない。最終分類用の
   厳密な帰属判定ルール(「中核責任に属すると説明できる場合のみ保持」等)を
   スクリーニングに書いてはならない。
2. 判定基準は目的そのもの: 「そのラベルの開発部署の担当者が関連技術として
   検討する理由が全く想定できない場合のみ除外。迷ったら保持」。
   除外側に立証責任を置く。
3. 冒頭にドメイン宣言: 「画像形成装置(プリンタ・複合機等)関連の特許分類」
   であることを必ず書く。
4. 中間推論を出力スキーマで強制: 判定フィールドより前に「工程推定」
   オブジェクトを置き、(a)請求対象が組み込まれる最終製品レベルの装置と用途、
   (b)扱う対象物の全列挙と各対象物がどこから来てどこへ行くか、
   (c)装置全体の工程位置(画像形成の前/中/後/無関係)を記入させる。
   思考指示を本文プローズだけに書いて済ませない。
5. 代表例の扱いは禁止形で: 「代表例はあくまで例示。代表例に同種の装置が
   無いことを除外理由にしてはならない。定義文と工程推定の重なりで判断」。
6. 除外理由の書式指定: 列挙した対象物名を挙げて、どれとも候補定義が
   重ならないことを具体的に書かせる(判定基準の文言コピペを防ぐ)。
7. 単段・短文: 多段階化や長文ルールの追加は禁止。上記構造(目的/判定手順/
   STEP0/候補/出力スキーマ)のみで構成する。



   # 目的
   これは画像形成装置(プリンタ・複合機等)関連の特許分類の一次スクリーニングである。
   特許のプロファイル(STEP0)を読み、各候補について「そのラベルに対応する開発部署の
   担当者に読ませるべきか」を決める。
   除外してよいのは、担当者が関連技術として検討する理由が全く想定できない候補のみ。
   検討する可能性が少しでも想定できるなら保持する。迷った場合は保持する
   (取りこぼしの方が誤保持より重大)。ここでの保持は採択ではない。最終分類は後段で行う。

   # 判定手順
   1. 判定の前に、STEP0のみから次を推定し、出力の「工程推定」に必ず記入する。
      - 請求対象が組み込まれる最終製品レベルの装置と、その一般的な用途
         - その装置が扱う対象物を漏れなく列挙し(複数あれば全て)、各対象物が
              どこから来てどこへ行くかを常識の範囲で補完して1行ずつ書く
                 - 装置全体としての工程位置(画像形成の前/中/後/無関係)
                    ただし、通常用途にない特殊な使い方を仮定してはならない。
                    2. 各候補は、機構の類似ではなく「担当範囲の定義」の文言と工程推定との重なりで
                       判断する。代表例はあくまで例示であり、代表例に同種の装置が無いことを
                          除外理由にしてはならない。
                          3. 除外する場合、理由には、工程推定で挙げたどの対象物・工程位置とも候補の定義が
                             重ならないことを、対象物名を挙げて具体的に書く。
                             4. STEP0の責任階層や担当者の優先順位はここで決めない。
