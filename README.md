1つ目は案2そのもの。顧客向けに言い換えると「関連あり公報のうち、言い換えの項（方法・プログラム項など）を学習から外します。それがテーマの言葉だけ共通するノイズを関連ありに押し上げていました。外すと除去率X%→Y%（交差検証）」。顧客のラベルが悪いとは一言も言わない。こちらの教え方を直す話。4の後に残った項を数える確認が、そのまま「外す対象のリスト」になる。
2つ目は顧客が言っていた「古い特許」の線。誤検知の近傍にいる関連あり例の年・種別・出願人の内訳を、学習データ全体の内訳と比べる。古い年代や特表や特定出願人に偏っていれば、「その塊の関連ありを学習から外す」で誤検知の周りの関連あり例が減るので、動く。偏っていなければ、外せる塊は無い。
どちらかが当たれば「これを外してください、X→Y%」が言える。両方外れたら、「外して良くなる塊は無い」が答えで、それは顧客が欲しい答えではないが、嘘よりはいい。
まず近傍の内訳2本（公報内で最高点でない項の割合、年・種別・出願人の偏り）を出してから、提案の形を決める。
