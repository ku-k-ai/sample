検索式自動提案システム Codex指示書（ブラインド検証用・リーク無し）
2026年10月22日 · @GPT
この文書の使い方
この文書は、答え（見つかった無効資料）を知らないCodexに方法だけを渡して、2案件で同じ結果が再現するかを確かめるためのもの。案件固有の語、実際に使った行、見つかった文献の番号、どの脚で入ったかは一切書いていない。
Codexに渡すもの：この文書、対象特許の番号、無効にしたいポイント1文（10節の2案件分）、日立の構文情報（12節をユーザが埋めたもの）。
Codexに渡さないもの：無効資料の番号、過去に人やClaudeが組んだ行と式、母集団の件数、入った脚。これらは別文書（答え入り）にあり、ブラインド結果が出た後の照合にだけ使う。
途中でCodexが「例を見せてほしい」「正解の文献を教えてほしい」と求めても渡さない。方法が足りないなら、方法の記述を直す。
システムの目的と入出力
対象特許と無効ポイント1文から、日立の検索システムにそのまま貼れる検索式一式を生成する。母集団（目安2000件）に対象特許が構造的に入ること、無効資料が入る確率を人の式より下げないことが目標。途中で人に質問しない。決めたことは出力に理由付きで添える。
設計の原則は5つ。
• 検索語は対象特許の本文の文字列から作る。請求項の語はそのまま使わない。これが対象特許が入る保証の根拠になる。
• 件数を減らすために語を削らない。削るのは針を削ることになる。件数は脚の構成、日付、書き出しの単位で調整する。
• 近傍検索が無い道具では、複合語（二語以上が一語に畳まれた名詞）を近傍の代わりに使う。
• 語彙に依存しない脚（引用文献の番号）を必ず持つ。
• 部品の位置関係を述べる言い回しは、物の名前とは別の脚にする。
入力は3つ。対象特許番号（公開・登録・USいずれも可。USならファミリーの日本公開を使う）、無効にしたい請求項番号（任意。無ければ無効ポイントから推定し、その旨を出力する）、無効にしたいポイント1文。任意で、日立の検索式サンプル、検索項目一覧、番号書式、本文取得に失敗した場合の対象特許PDFまたはテキスト。
出力は5つ。全て人がそのまま貼れる形にする。
1. 行表：式番号、検索項目、キーワード（空白区切り、200バイト以内）、検索方式（一致検索(OR)）。
2. 検索論理式：母集団用、脚別、確認用（日付行を公開番号行に替えたもの）、予備（複合語も日付も使わない本文語だけの式）。
3. 根拠表：語ごとに、点（錨・物A・関係R・相手B）、欄（7つの呼び方のどれか、または総当たり）、出典（本文の段落・符号・起案者の列挙・背景技術・LLM推定）、対象特許の本文で一致した文。
4. 運用手順：打つ順番、確認の仕方、件数の削り規則、書き出しの単位。
5. ローカル検証結果：各脚が対象特許の本文に当たるか、当たった文、プローブ（引用文献）の再現率。

パイプライン全体
11ステップを順に実行する。9で失敗したら8に戻る。11は母集団を読んだ結果（次のプロジェクト）が出てから回す。
1. 入力解釈：番号の正規化、ファミリー解決、優先日の確定、請求項番号の確定。
2. 本文取得：Google Patents の /ja ページから公開（A）と登録（B2）を取得。失敗時はユーザ提供テキスト。
3. 構成要件分解：指定請求項（従属なら親込み）を要件に分け、無効ポイント1文に対応する要件を特定し、物A・関係R・相手Bに分ける。
4. 本文語の抽出：符号で請求項の語を本文の実体に落とし、3点と錨の文字列を位置付きで抜く。起案者の列挙、背景技術、課題・効果も抜く。
5. 語彙生成：点ごとに7つの呼び方の欄を埋める。複数回生成して多数決。
6. 複合語の総当たり生成：部品語×機能語×部位語。
7. 引用番号の収集：審査官引用、先行技術文献、その登録番号、ファミリー、被引用。
8. 脚の組み立て：L1〜L5を作り、行に分割し、式を生成する。
9. ローカル検証：対象特許の本文で各脚を判定。L1が偽なら8に戻る。プローブがあれば再現率の代理を出す。
10. 出力：行表、式、根拠表、運用手順、検証結果。
11. 事後学習：針が見つかったら、入った脚と針の呼び方を台帳に記録し、生成規則を見直し、全案件でリグレッション。
ステップ詳細1：本文取得と構成要件分解
請求項の語は検索語にしない。本文の語に翻訳してから使う。以下の例は説明用の架空の案件（自転車のチェーンカバーの取付構造）で、検証する2案件とは無関係。
取得する欄：名称、出願人、出願日・優先日、公開番号、登録番号、請求項（公開と登録の両方）、技術分野、背景技術、先行技術文献（特許文献の番号）、課題、手段、図面の簡単な説明、実施形態、符号の説明、要約、引用文献（審査官引用の印付き）、ファミリー。Google Patents は一部ページを robots で弾くことがある。弾かれたら本文を要求して止まらず、取得できた範囲で進め、出力に明記する。
構成要件分解の規則：
• 指定請求項を要件に分ける。従属項なら親の要件を含める。
• 無効ポイント1文に対応する要件を特定し、物A・関係R・相手Bに分ける。例：「カバーの縁部がフレームの段差に沿って取り付けられる」なら、物A＝カバーの縁部、関係R＝沿って取り付けられる、相手B＝フレームの段差。
• 請求項の語を符号の説明で本文の実体に落とす。「縁部」が本文では「フランジ１２」なら、語彙生成はフランジ１２に対して行う。
• 補正で入った文言を検出する。登録公報と公開公報の請求項の差分を取り、差分にしか無い語は本文の表現に翻訳する。翻訳元と翻訳先を根拠表に残す。本文に無い語を検索語にしない。
• 錨は仕組みの物理的な主役にする。応用分野（自転車、車種）は錨にしない。分類コードは AND しない。
• 無効ポイントが位置関係や数量（複数、同一、沿って、間）を述べている場合、本文では個別の部品名と配置の言い回しで書かれているはずなので、その文を見つけて関係Rの本文語にする。

• 各欄を N 回（既定5回）、立場を変えて（起案者、審査官、別業界の設計者、昔の技術者）生成し、2回以上出た語を標準、1回だけの語を広い版に回す。
• 欄7は、無効ポイントの要件が位置関係・数量・順序を含むとき必ず埋める。先行文献は数を数えずに個別の部品名と配置で書くので、数量語（複数、二つ）だけに頼らない。
• 多義語は LLM に判定させ、単独では使わず複合語か相手語との AND でのみ使う。
• 単漢字は禁止。半角英数字を含む語は全角にする。
• 一般語は削らない。件数は脚で扱う。
複合語の総当たり：部品語×機能語（×部位語）を機械的に掛け合わせ、全て行に入れる。LLM が選ぶのではなく、積を作る。
• 型：（物Aの呼び名）×（受ける側の機能：保持、収容、受け、座、支持、固定、取付、装着、嵌合、係止、位置決め、規制）(+部)。
• 型：（受ける側の機能）×（部位：凹部、溝、穴、孔、壁、面、空間）。
• 型：（相手Bの呼び名）×（同じ機能語）。
• 複合語は文の共起が一語に畳まれたものなので、近傍検索の代わりになる。行の件数が数十万を超える語は複合語になっていないか、分割されている。

式の形：
( L1 + L2 + L3 + L4 + L5 ) * 日付
入れ子は脚の内側一段まで（例：(1+2)*3*(4+5)）。全体で通らない場合に備え、脚別の式と、脚なしの予備式（錨 AND 本文語A AND 本文語B）も必ず出す。
守る規則：
• NOT は使わない。分類コードは AND しない（使うなら OR の脚）。
• 一般語は削らない。件数の調整は脚の増減、日付の分割、書き出しの単位で行う。
• 日付は優先日の前日で :YYYYMMDD。拡大先願を狙う場合の出願日基準はユーザ判断。
• 合計の目安は2000件。超えたら脚別の件数を出し、最大の脚の最もありふれた語から外す。L4 は触らない。1000件を超える脚は日付で二分する。
• 行は200バイトで自動分割し、分割した行を式で + で結ぶ。
• 審査引例・参考文献の番号は「特開2003-12345」「特開平8-1234」の形式で出す。本文側は半角、全角、ゼロ埋めを並べる。番号は書誌から機械生成し、手打ちしない。
予算に収める順序（超えたときに上から順に削る。L1 の本文語と L4 の配置語は削らない）：
1. 番号の表記揺れは半角ハイフン1種とゼロ埋め1種だけにする。外国番号は入れない。審査引例・参考文献は欄指定で各1行、本文側の番号は1行にまとめる。日立側が全角を半角に正規化するなら表記揺れの行は不要（同じ番号を全角と半角で打って件数が同じなら正規化されている）。
2. カタカナ異表記ONで吸収できる表記揺れを外す。
3. 1回しか生成されなかった語（広い版）を外す。
4. L5（相手側複合語）を落とす。
5. 業界の品名の欄を外す。
ステップ詳細4：ローカル検証とプローブ
式を出す前に、対象特許の本文で式を評価する。L1 が真でなければ出力しない。
• 判定器：行のキーワードのいずれかが対象特許の本文（要約＋請求項＋明細書＋符号の説明）に部分一致すれば行は真。式の * と + をそのまま評価する。日付行は評価から除く（対象特許は自分の優先日より後に公開されるので必ず偽になる）。
• 根拠：真になった行ごとに、一致した文を前後30字付きで根拠表に出す。
• プローブ：審査官引用、先行技術文献、被引用のテキストが取れたら同じ判定を掛け、脚ごとに何本拾えたかを出す。針は測れないが、同じ概念を他人が書いた実在文献に対する再現率は測れる。
• 行の件数：日立の画面に出る行ごとのヒット件数を入力できるようにし、数十万件を超える行には一般語か分割語が混ざっているとして警告する。
• 既知の針がある案件は、対象特許と針の両方を固定テストにする。生成規則を変えたら全件を再評価する。ただしこの文書で行うブラインド検証の間は、針の番号をシステムに入れない。
出力フォーマットと運用手順
出力は人が画面に貼って順に打つだけで終わる形にする。式は4種類、手順は7段。
行表の列：式番号、検索項目、キーワード、検索方式。キーワードは空白区切り、200バイト以内、全角統一、単漢字なし。番号行は「特開2003-12345」形式、日付行は「:YYYYMMDD」、確認用に公開番号行を1行用意する。
式の種類：
1. 母集団用：( L1 + L2 + L3 + L4 + L5 ) * 日付。
2. 脚別：各脚に日付を掛けた式。件数の内訳と書き出しに使う。
3. 確認用：日付行を公開番号行に替えた式。対象特許の公開番号で1件になれば入っている。
4. 予備：錨 AND 本文語A AND 本文語B（複合語も日付も無し）。確認用で0件のときの切り分けに使う。
運用手順（この順で出力に書く）：
1. 公報種別を公開特許、公開実用、実用、特許にし、カタカナ異表記をONにする。
2. 行を貼る。エラーが出たら行番号が示されるので、その行の番号書式を直す。
3. 確認用の式で対象特許が1件になるか見る。日付行は入れない。0件なら予備式を打ち、それも0件なら索引か構文の問題。
4. 母集団用の式で件数を見る。2000以下ならそのまま。
5. 超えたら脚別の式で内訳を出し、最大の脚の最もありふれた語を外して再計算する。L4 は触らない。
6. 脚ごとに書き出す。1000件を超える脚は日付を二分する。
7. Excel で公開番号の重複を消す。番号欄が出願番号表示のことがあるので、公開番号・出願番号の両方で突合する。
ブラインド再現テストの手順と合格基準
合格は、Codexが方法だけから組んだ式で、2案件とも対象特許と無効資料の両方が母集団に入り、かつ母集団が基準件数以内に収まること。無効資料の番号は人だけが持ち、Codexには最後まで渡さない。

2. 同じ入力で生成を3回繰り返し、3回分の行と式を保存する。LLMのぶれを見るため。
3. 人が日立で、各回の確認用の式で対象特許が入るかを見る（日付なし）。
4. 人が各回の母集団用の式で件数を見て、無効資料の公開番号でANDして入るかを見る。入ったなら脚別の式でどの脚か記録する。
5. 台帳に記録：案件、回、件数、対象特許の有無、無効資料の有無、入った脚、Codexが選んだ錨と3点。
6. 3回とも通れば合格。2回なら「ぶれあり」として、落ちた回の行を答え入り文書の行と比べ、方法の記述のどこが足りなかったかを特定する。足りない記述を直して再度3回。
7. 一度も通らない案件があれば、落ちた理由を種別・フィールド・錨・語の順で切り分け、方法の記述を直す。無効資料の語を文書に足すことはしない。
合格基準：
• 対象特許：3回とも、確認用の式で1件。
• 無効資料：3回とも母集団に入る。
• 件数：母集団が3000件以下（2000件が目安、超過は脚別の削り規則を適用した後の値で判定）。
• 根拠表に、無効資料の番号や語が現れないこと（現れたら方法ではなく記憶で組んでいる）。
テスト後にだけ、答え入りの文書（実際に使った行、入った脚）を開いて照合する。照合の目的は、Codexの行が人の行と一致することではなく、方法の記述の抜けを見つけること。
