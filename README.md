誤検知ノイズの近傍分析 — Codex作業指示
2026年10月27日 · @GPT
目的と範囲
学習済みBERT自身の表現空間で、誤検知ノイズの近傍にどの学習請求項がいるかを、対照群と並べて数値化する。それだけ。原因の最終判断、モデル改善、顧客向け資料はこの作業の外。
• 対象：判定データ（学習未使用）の正解ノイズ102件。うち80件が「関連あり」と判定（FPノイズ）、22件は正しくノイズ（TNノイズ）。関連あり側（TP）は対照群として使う
• 深掘りする1件：特表2026-510516。3独立項×3fold＝9スコアがすべて0.8以上
• 判定の仕組み（変更禁止）：独立項ごとにBERTでスコア、3foldのスコアを平均、閾値は各foldのvalidでFβ=1.5最大の値を平均したもの、特許単位は独立項のOR
• 決めたいこと：FPノイズ80件の各請求項を、A（同文級の関連ありが学習側にいる）／B（近傍から遠く、priorに倒れている）／C（近傍にノイズがいるのに関連あり）に振り分け、件数を出す。定義はStep 6
やらないこと
読み取り専用の作業。迷ったら止めて質問し、方針を自分で変えない。
• TRAK、全層の影響関数、再学習、学習例の重み変更実験はしない
• モデル、閾値、学習データ、前処理、集約ルールを変更しない
• 本番の前処理・推論コードを再実装しない。既存コードを呼ぶ。独立項の切り出し、max_length、トークナイザは本番と同一
• fold間でベクトルやスコアを混ぜない。表現空間はfoldごとに別物
• 2次元可視化（UMAP、t-SNE等）を根拠にしない。作るなら補助図として最後に1枚だけ
• 数値と解釈を混ぜない。解釈は報告の末尾「所感」に分ける
• 本番スコアが再現しない、ファイルが見つからない、ラベル列の意味が不明、などは止めて報告
Step 0 環境確認と再現
次を特定してパスを報告し、再現確認が通ってから Step 1 へ進む。
1. 3foldモデルの保存先（fold 0/1/2）とトークナイザ。アーキテクチャ名（BertForSequenceClassification か、それ以外か）と classifier モジュールの構造（Linear 1層か、dense→out_proj の2層か）
2. 各foldの学習／valid分割ファイル。独立項単位の行数と、関連あり：ノイズの件数（prior）をfoldごとに表にする
3. 判定データのファイル。ノイズ102件、関連あり件数、特許ごとの独立項数の分布
4. 本番と同じ推論スクリプト。独立項の切り出し、max_length、バッチ処理、fold平均、閾値（fold別の値と平均値）、特許単位のOR
5. 再現：本番手順で特表2026-510516の3独立項×3foldの9スコアを出し、すべて0.8以上であることを確認。fold平均スコアと平均閾値も記録
再現しない、または閾値や分割が複数バージョンあって本番のものが特定できない場合は止めて報告する。
Step 1 表現ベクトルの抽出
classifier の入力を forward hook で横から読む。モデルは改変しない。logit と確率 p も同じ forward で保存する。
model.eval(); feats = []
hook = model.classifier.register_forward_hook(
    lambda m, inp, out: feats.append(inp[0].detach().cpu()))
logits = []
with torch.no_grad():
    for batch in loader:            # 本番と同じ前処理・バッチ
        out = model(**batch)
        logits.append(out.logits.detach().cpu())
hook.remove()
H = torch.cat(feats)                # (n, 768) 最終層が見ている表現
L = torch.cat(logits)               # (n, 2)  本番と同じ p を計算する元
• BertForSequenceClassification なら model.bert(**batch).pooler_output と一致する。1バッチで一致（最大絶対差）を確認してから本番
• RoBERTa／DeBERTa 系で classifier が dense→out_proj の2層なら、フック先は model.classifier.out_proj
• 対象（foldごと、f=0,1,2）：(a) fold f の学習請求項すべて（独立項単位）、(b) 判定データの全請求項。関連ありが多すぎる場合は特許単位で層化サンプル500件、seed固定
• 保存：fold別に rep_fold{f}_train.npz と rep_fold{f}_eval.npz。列は h、logit、p、label（1＝関連あり）、patent_id、claim_id、text。dtype は float32
• (b) の p を fold平均し、Step 0 の本番スコアと一致することを確認してから Step 2 へ
Step 2 近傍分析（foldごと）
判定請求項ごとに学習請求項の top-k を取り、FPノイズ・TNノイズ・関連ありの3群で分布を比べる。「近傍に関連ありが多い」は prior と比べて初めて意味を持つ。
1. h を L2 正規化し、判定請求項 t と fold f の学習請求項全件の cos 類似度を行列積で出す（メモリに応じてチャンク、k=20）
2. 各 t に記録：top1 cos、top1 label、top1 text、top-k 関連あり率、top-k 平均 cos、top-k の p の平均
3. prior：fold f の学習請求項の関連あり率。各 t の「top-k 関連あり率 − prior」を出す
4. 群分け（請求項単位）：FPノイズ＝ノイズ特許の請求項で fold平均 p が平均閾値以上、TNノイズ＝同じく閾値未満、TP＝関連あり特許の請求項で閾値以上
5. 特許単位の表も作る。代表請求項は本番と同じく fold平均 p が最大の請求項

Step 3 後押し／抑制（最終層・一次近似）
再学習なし、行列積1回で「どの学習例が同方向に引いているか」を順位付けする。「だから 0.9 になった」の説明ではない。報告にその一文を必ず入れる。
s_i = (y_i - p_i)\,(h_i \cdot h_t)
• y_i：学習例 i のラベル（1＝関連あり、0＝ノイズ）
• p_i：同じ fold モデルが学習例 i に出す確率（Step 1 の train 側で保存済み）
• h_i、h_t：正規化前の表現ベクトル。学習例 i と判定請求項 t
• 各 t に出す：正の合計 S+、負の合計 S−、比 S+/|S−|、上位10例ずつ（text、label、cos、p、s_i）
• Step 2 と同じ3群で S+/|S−| の分布を比べる。FPノイズだけ比が大きければ「関連ありの学習例が一方向に引いている」、TNノイズと同程度なら近傍では説明できない
Step 4 例の1件（特表2026-510516）
3独立項それぞれについて、fold 別の top-10 を文面付きで並べ、top-1 との差分を出す。
1. 表：独立項 × fold ごとに top-10（順位、text、label、cos、p、s_i）。3独立項 × 3fold ＝ 9 表
2. 3fold での top-10 の重なり（claim_id の Jaccard）。揃えば学習データの総意、fold ごとに違えば偶然寄り
3. 各独立項の top-1 と、対象請求項の文面 diff（difflib の unified diff）。ほぼ同文ならそれが答え
4. 3独立項に共通して上位に来る学習請求項があれば、その特許番号と請求項を列挙
ファミリーや出願人の照合はしない。同文級の請求項は cos だけで浮く。
Step 5 語彙ベースライン（TF-IDF）
人の判断を使わずに「請求項の語彙に情報があるか」の下限を出す。BERT と同じ分割・同じ閾値決定・同じ集約で作らないと比較にならない。
1. 特徴量：TF-IDF、文字 2〜4gram（形態素があるなら単語 1〜2gram も別途）。学習側のみで fit
2. 分類器：ロジスティック回帰（class_weight は本番 BERT の損失設定に合わせる。合わせられなければ none と balanced の両方）
3. 分割：BERT と同じ 3fold。閾値：各 fold の valid で Fβ=1.5 最大 → 平均。集約：fold 平均 → 特許単位で独立項の OR
4. 判定データで出す：ノイズ側 Recall、関連あり側 Recall、F1.5。BERT の同じ数値を横に置く
5. 重なり：FPノイズ80件のうち TF-IDF でも関連ありと出た件数。特表2026-510516 の TF-IDF スコアも記録
読み方：TF-IDF のノイズ側 Recall が BERT と同程度なら、語彙に情報がない＝請求項の外の話。TF-IDF が大きく勝つなら BERT 側の問題。
Step 6 FPノイズの分類（A／B／C）
FPノイズの各請求項を、対照群の分布を基準に振り分ける。固定の閾値ではなく TP群・TNノイズ群の中央値を基準にする。基準値は報告に明記する。

top1 が関連あり、かつ top1 cos ≥ TP群の top1 cos 中央値

B 遠い

C 近傍無視

• 1件が A と C の両方に当たる場合は A を優先し、両方に当たった件数を別に出す
• fold ごとの区分が割れる件数も出す（3fold で一致した件数／割れた件数）
