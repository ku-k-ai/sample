要点は「関連あり寄り」のほう。
近傍の数字をそのまま読むと、この80件は学習データの中では関連あり側に座っている（関連あり側cos 0.70、Other側0.66、近傍の関連あり率は＋0.34）。未知の領域じゃない。「学習データの関連ありに似ていて、学習データのノイズには似ていない」場所。だからモデルは教わった通りに関連ありと言う。間違えたというより、教わった区別をそのまま適用した。
「でも遠いなら自信は下がるはず」が自然な感覚だけど、ニューラルネットはそうできていない。最終層は1枚の境界面で、自信は「境界面からの距離」であって「学習データからの距離」じゃない。境界面は学習データの外まで無限に伸びていて、データの薄い場所でも関連あり側に落ちれば0.9を出す。「見たことがない」という出力は存在しない。請求項9のモデル0がまさにそれで、最も近い関連あり例とノイズ例への距離が同じ（0.633と0.634）なのにp 0.80。近さじゃなく方向で決まっている。
じゃあなぜ方向が関連あり側になるのか。学習データのノイズが「テーマ外」だからだ。正しく弾けた22件の近傍は強くノイズ側（−0.47）＝学習データのノイズは文面で明らかにテーマ外で、モデルはそれを完璧に学んだ。モデルが学んだ境界は「テーマ内か、テーマ外か」。この顧客の判定データのノイズ80件はテーマ内のノイズで、テーマの語彙で書かれているから境界のテーマ内側に落ちる。TF-IDFが同じ70件を間違えるのも同じ理由。単語の袋にもテーマの単語が入っている。22件は弾けて80件は弾けない、という割れ方自体がこの説明の証拠。
だから結論は「仕方ない」じゃなく、こう。モデルが答えている問いは「テーマ内か」、顧客が答えてほしい問いは「テーマ内のうち、うちの基準で関連ありか」。学習データにテーマ内ノイズが無いので、2つ目の区別を教わっていない。君が前に言った「最初の顧客と今回の顧客は見てる特許の性質が違う」の中身がこれで、最初の顧客のノイズは検索式由来のテーマ外、今回のノイズは目視判断由来のテーマ内。
教われば学べるかは別問題で、それがH1/H2。線形プローブは「凍結した表現の中に、テーマ内ノイズと関連ありを分ける軸がもう存在するか」を見る。あるなら境界を引き直す材料（テーマ内ノイズの例）が無かっただけで、判定データの80件がそのまま材料になる。無いなら、請求項の文面にその区別が無い。
