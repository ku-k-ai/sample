# 特許の届け先分類：STEP2と最終判定の差し替え

**会社のCodexは [CODEX_START.md](CODEX_START.md) から着手する。**

既存の段階構成（STEP1 → STEP2_PLAN → STEP2_REVIEW → FINAL_DECISION）はそのまま。直すのは、正解の候補がSTEP2で落ちる経路と、最終判定の問いの2つ。

| ファイル | 中身 |
|---|---|
| `prompts/final_decision_v4.txt` | 最終判定プロンプト。「請求物は何か」「特徴部分は何のための構成か」で担当ユニットを決め、それを受け持つ候補を選ぶ。STEP1/2の表は入力に残す |
| `prompts/step2_review_patch.md` | STEP2_REVIEWのプロンプトの差し替え2か所（確認済みの定義、判定対象外の定義） |
| `patent_pipeline/guards.py` | 段階間の検査。判定対象外は確認済みの事実が必要、本文確認が必要の候補も最終段へ、v4出力の検査、プロンプト組立 |
| `tests/test_pipeline_guards.py` | 合成データの検査テスト37本 |

## 何が悪かったか

1. **STEP2が「見つからない」ことで候補を落としていた。** 判定対象外の定義が「全文を読んでもつながりを確認できない」で、検査コードもそれを通していた。画像形成後の紙を扱う装置の案件で、正解の後処理系の候補がこれで落ちた。
2. **STEP2が字面で確認していた。** 確認事項に定義の語（「紙」）が入っていると、本文の同じ意味の記載（「シート」）を見つけても、字が違うことを理由に未確認にした。
3. **最終判定が、担当範囲の語と請求項の語の照合になっていた。** ユニット内部の回路の特許が技術担当に、ユニットを引き出すための外装の特許が本体・給紙に引っ張られた。
