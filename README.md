数字は出た。方向は予測通りで、確定の言い方はAstraの修正を受ける。
同じ条件（同じモデル・同じ閾値・分割単位・公報未見）で、validのノイズ除去率56〜64%に対して判定データは28〜31%。この顧客のノイズは、モデルが自分の未見ノイズを弾く力の半分しか弾けない。これは観測として確定。なぜ半分か（テーマ内ノイズの不足か、基準の違いか）は未確定。Astraの言う通り。ただし、どちらであっても次の2手（顧客への3列、hard negativeのプローブ）は同じなので、未確定のまま動ける。
数字の見え方も変えたほうがいい。本番の21.6%とvalidの69.3%を並べると4倍差に見えるが、揃えると60対30で2倍差。しかも60%のほうが「このモデルが未見の特許に対して出せる素の力」で、最初の顧客で良く見えたのはノイズが易しかった分。顧客にも社内にも、この2倍差のほうを話すべき。
副産物を一つ。validの71%が同じ特許の別分割を学習済み、つまりfoldが請求項単位で切られていて、特許単位で見れば漏れている。69.3%はその分だけ膨らんだ数字で、閾値0.27もその条件で選ばれている。今回のFPはp 0.85以上だから原因ではないが、次にhard negativeを足して再評価する時に特許単位のGroupKFoldにしないと、改善が水増しで出る。
プローブの読みはAstraが正しい。2段目を足すと全体Recallは掛け算で落ちる。98.6%を98%に保つには2段目で99.4%、TP117件なら許される見逃しが0.7件。閾値は実質「一番スコアの低いTP1件」で決まる、使い物にならない運用点になる。だからプローブは「表現に情報が残っているか」の試験として読み、残っているなら2段構えじゃなく、判定データのノイズを学習に足して本体を1段で学習し直す。評価は特許単位CVで端から端まで。
顧客への3列は、Astraの問い方に乗り換える。「この3件を今回の基準で分類するとどうなりますか。何が判断を分けますか」。学習側の関連ありが今回の基準でノイズと言われたら、基準のずれがその場で確定する。10組。
ついでに判定データでのトレードオフ曲線（閾値を動かした時のノイズ除去率と関連ありRecall）を1枚付ける。設計を変える話じゃなく、運用点を顧客に選ばせるための情報。
Astraと俺で残っている差は言葉だけ。動く順は、3列の10組を作る → validの表現抽出とプローブ3方式（特許単位CV、閾値は学習側で決定、全体Recall≥98%でのノイズ除去率） → 顧客に3列と曲線を持っていく。
