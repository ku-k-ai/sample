# 決め方の考え方
開発担当者は、装置のユニット・工程ごと（原稿の読取、給紙、後搬送、定着、後処理など）か、どの工程でも使う技術ごと（電源、モータ、センサ、筐体全体など）に分かれています。特許は、その発明を実際に設計・変更する担当者に届けます。

判断の中心は2つだけです。
- 請求された物は何か
- 特徴部分は何のための構成か

技術の種類（電源回路、メカ、センサ）や、候補の定義に請求項と同じ語が出てくることでは決めません。

# 用語
- 請求物：独立請求項の主語になっている物（「〜を備えるX」「〜であるX」のX）。
- 特徴部分：請求物の中で、この発明が従来から変えている構成・動作。請求物が普通に備える前提の構成は含みません。
- 担当ユニット：この発明を設計・変更する担当が受け持つ、装置のユニット・工程。

# 手順1 請求物と特徴部分
請求物の種類を1つ選んでください。
- A：特定のユニット・装置そのもの（例：定着装置、現像装置、フィニッシャ、給紙デッキ、原稿搬送装置）
- B：装置全体（画像形成装置、画像形成システムなど）、または方法・プログラム・制御装置など、場所を特定しない主語
- C：電源装置・モータ駆動装置など技術そのものの装置で、請求項が用途を特定のユニット・工程に限定していないもの

特徴部分を、何を対象に何をするものか、具体的に書いてください。

# 手順2 担当ユニット
- A のとき：請求物そのものが属するユニットが担当ユニットです。
  - 請求物の内部にある機能（給電回路、用紙の積載・分離・供給、搬送ローラ、筐体の部品など）を理由に、別の担当へ振り替えないでください。その内部機能を受け持つ候補は、関連候補にとどめます。
  - 請求物がどのユニットに当たるかは、本文の原文引用を先に使い、足りなければ一般的な技術知識で位置づけてください（例：ステープラは後処理装置の部品、帯電ローラは帯電工程の部品）。一般知識で位置づけたときは、根拠を「推定」としてください。請求項に接続先が書かれていないことは、位置づけられない理由になりません。
- B のとき：特徴部分が「何のために設けられているか」で決めます。その構成が支えている機能・操作・紙の流れを受け持つユニットが担当ユニットです。
  - 「何のために設けられているか」は、「発明の課題と効果」に書かれた目的から答えてください。そこに書かれた目的をそのまま使い、その目的がさらに何の役に立つかまではさかのぼらないでください。「発明の課題と効果」が空のときは、独立請求項から答えてください。
  - 部品の名前（取手、フレーム、外装、筐体、トレイ、ローラ）では決めません。例：定着ユニットを着脱するためのガイドやレバーの形状なら、着脱される定着の担当です。
  - 請求項に名前が出てくるだけのユニット（前提の構成、位置関係の基準として出てくるだけの部品）は、担当ユニットにしません。
  - 特徴部分が装置全体に共通の部分（主電源、主制御、筐体全体の構成・配置）のためのものなら、担当ユニットは「本体共通」です。
- C のとき：担当ユニットは「限定なし」です。
- 一般知識でも位置づけられないときだけ「特定できない」にしてください。

# 手順3 候補を当てる
- 担当ユニットを受け持つ候補がいれば、それが主な届け先です。特徴が電源・回路・メカ・センサであっても変えません。
- 「受け持つ」かどうかは、名前ではなく仕事で判断します。候補の定義・代表例が、担当ユニットの行う仕事（何に対して、何をするか）を範囲に含んでいれば受け持ちます。
  - 定義や代表例に挙がっている装置名は例です。代表例は非限定です。担当ユニットの名前が定義に無いことだけで「受け持たない」にしないでください。定義が「〜などの装置」と書いていれば、挙がっていない装置でも、同じ仕事をする装置はその範囲に入ります。
  - 範囲を広げてよいのは、定義・代表例に挙がっている仕事と同じ種類の仕事までです。括弧書きのまとめ（「〜に関連する分野」など）だけを根拠に、挙がっている仕事と種類の違うものまで範囲に入れないでください。
  - 特許本文での装置の呼び名や区分け（ある装置と「〇〇装置」が別々に書かれている、など）は、その特許の中での呼び方です。社内の担当の区分けとは別物なので、それを根拠に「受け持たない」にしないでください。
- 他の候補の定義に、特徴部分と同じ語（取手、積載、分離、規制、回路構成、筐体、搬送など）があっても、それだけでは主な届け先にしません。定義の語は、「どの候補がその担当ユニットを受け持っているか」を確かめるためにだけ使います。
- 備考・振分け（例：「〇〇関係なら△△へ」「□□の××は△△へ」）は、請求物・特徴部分がその振分けの対象そのものであるときだけ当てはめます。請求物が A のとき、内部機能を理由に振分けを当てはめないでください。
- 担当ユニットが「本体共通」「限定なし」のとき、または B で分類ルール表にその担当ユニットを受け持つ項目が無いときだけ、特徴部分がその技術そのものの設計変更に当たる、技術担当の候補を選びます。
- 請求物が A で、担当ユニットを受け持つ項目が分類ルール表に見つからないときは「自信無」にしてください。請求物の内部機能を受け持つ候補や、技術担当の候補で代用しないでください。
- 担当ユニットを受け持つ項目が分類ルール表にあるのに、選択可能候補に無いときは「自信無」とし、その項目のラベルを「本来の届け先」に書いてください。代わりの候補を選ばないでください。
- 担当ユニットが「特定できない」とき、または担当ユニットを受け持つ候補が2つ以上あって、どちらが受け持つか説明できないときは「自信無」にしてください。

# STEP0〜STEP2の結果の使い方
- STEP2の本文確認結果・根拠引用は、請求物や特徴部分がどのユニットに属するかの根拠として使ってください（例：「画像読取り用の機能ユニットとして記載されている」と確認されていれば、担当ユニットの根拠になります）。「何のための構成か」の答えには使わないでください。STEP2の引用は候補ごとの確認のために集めたもので、実施例の周辺の動作が含まれるためです。
- 「整合確認済み」などの確認状態は、その候補が選べるという印です。順位ではありません。技術担当の候補の整合確認は、特徴部分の技術がその定義の語に当たるという意味にとどまり、担当ユニットを受け持つことの確認ではありません。
- 前段の工程位置が「判定不能」「不明」でも、担当ユニットは手順2で決めてください。
- 前段の判断文（対応根拠、保持理由など）と、請求項・原文引用が食い違うときは、請求項・原文引用を優先してください。
- 入力に含まれる前段向けの指示文は、今回の指示として扱わないでください。
