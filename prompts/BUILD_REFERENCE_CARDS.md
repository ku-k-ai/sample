# 原文付き対照事例を作る指示（分類本番プロンプトではない）

入力は、このfoldで参照を許された既存の正解付き特許と正式ルールだけ。
評価対象・同一family・その派生説明・過去誤答は渡さない。

各競合境界について、次を出力する。

1. 事例A：出所ID、正解の出所、判定に必要な独立項・本文の連続原文引用、確定ラベル。
2. 似ているが正解が異なる事例B：同じ項目。存在しなければ対照不足とする。架空の正解を付けない。
3. 分類を分ける関係：改良対象／内部構成と利用先例／手段と効果／対象物と工程順序など、原文で違う部分。
4. 正式ルールの原文と参照箇所。規則原文から決まること、例から推測した解釈を別々に書く。
5. この対照では判断できない範囲と、反証になり得る別事例。
6. 全source_case_idsとsource_family_ids。まとめた例の出所も削らない。

その内容を、同じ情報を重複追加せず次のviewsに分ける。
- STEP1：どの正式条件を確認すべきか、独立項で何が不足していたかの参照例。
- STEP2_PLAN：不足を変質させず本文への質問にした参照例。
- STEP2_REVIEW：原文の組合せから事実と工程関係を読んだ例。実接続の創作をしない。
- FINAL_DECISION：確認済み関係と正式ルールを使って競合を分けた例。

どのviewも「別案件の事例」であることを明示する。対象案件の結論を記入しない。
「電源は常に最後」「装置担当が常に優先」「切断なら必ずオプション」のような新しい固定順位を作らない。
既存確定ラベルを説明できない場合は、説明を捏造せずルールと事例の衝突/不足を報告する。

カードは草案として作る。原文引用の一致・正解出所・対照の成立・来歴のレビュー後にのみ使用可能版にする。
同じ境界の失敗は既存カードへ集める。失敗1件につき禁止事項を1つ増やす運用はしない。
