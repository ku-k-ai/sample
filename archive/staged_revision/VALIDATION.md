# 検証記録

## 実施済み

```text
python -m unittest discover -s tests -v
Ran 30 tests
OK
```

実施環境：作業用Python環境。すべて合成データを用いた段階間契約の検査。
実特許の正解ラベルをモックで返して精度検証したものではない。

検査内容：質問定型、正式ルールの引用元、確認IDの欠落・重複、計画の固定、原文引用一致、確認状態と条件判定の対応、未確認と不一致の区別、全文確認後の対象外化、代替条件、差戻し、STEP1と部分事実の保持、採用済み確認計画の引き継ぎ、旧結果混入、最終選択資格・主担当件数。

- 写真に写っていない特許本文まで含めた元案件の再実行。

文字列引用が一致しても、その引用から担当条件を導けるとは限らない。上の30テスト成功を分類精度の証明に使わない。

## 実LLMでの比較手順

1. 同じ請求項・候補・正式ルール・モデル設定でSTEP1を5回実行する。候補状態、必要条件、観点、対象・関係を比較する。文言の差と意味の差を分ける。
2. 最初のSTEP1出力を固定し、STEP2_PLANを5回実行する。不要な実接続条件、担当対象の脱落、OR/ANDの変質が出ないかを確認する。都合のよい出力を選んで固定しない。
3. 最初の妥当性確認済み計画を固定してSTEP2_REVIEWを5回実行する。引用の場所の差、得た事実の差、同じ事実に対する条件判定の差を別々に記録する。
4. STEP2出力を1つ固定して最終判定を5回実行する。資格を変えていないか、図面・制御仕様の対象をすり替えていないか、比較理由が一貫するかを確認する。
5. 既知の正解案件も含め、変更前後を同じ条件で比較する。一件だけ改善して他を悪化させた場合は成功としない。

固定する対象を変えたらrun_idを変える。モデルの途中の失敗や自信無も記録し、成功だけ集計しない。
